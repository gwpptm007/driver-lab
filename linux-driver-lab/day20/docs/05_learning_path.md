# Day20 学习路径

## Day20 真正要学什么

Day20 不是新驱动 API 学习日，它更像“工程闭环学习日”。

你会学到：

### 1. 如何定义回归对象

不是泛泛地说“系统能跑”，而是具体到：

- 启动到什么程度算成功
- 哪些节点必须可用
- 哪些 trace / perf 能力必须保留

### 2. 如何把一次性成功变成可重复成功

很多实验第一次能过，但第二次、第三次就不一定。  
Day20 学的就是如何把它固化成脚本。

### 3. 如何做失败分类

自动回归真正有价值的地方，不只是告诉你“失败了”，而是告诉你：

- 启动挂了
- debugfs 丢了
- 模块装不上
- trace 丢了
- perf 坏了
- dmesg 不干净

### 4. 如何给后续 Day21 服务

Day20 自动化以后，Day21 总结报告就不是“凭印象写”，而是有清晰回归依据可以引用。

## 建议的学习顺序

1. 回看 Day06 的回归脚本思路  
2. 回看 Day13 的 trace 路径  
3. 回看 Day17 / Day18 的 records 布局  
4. 再进入 Day20 的脚本实现  

## 一句话理解 Day20

> Day20 学的是：如何把一个已经跑通的技术链，做成以后还能稳定复用的自动化验证链。
