# day31：bench：吞吐/延迟/CPU 占用

## 1. 今日定位

- 周期：W5
- 后端设备：QEMU EDU（DMA-capable）
- 当日目标：做最小 bench，输出吞吐、延迟、p50/p99 和 CPU 占用，形成可比较的报表。

这一天不追求“大而全”，只追求把当天的关键链路做通，并且把证据沉淀下来。

---

## 2. 你今天真正要学会什么

- 知道 bench 指标必须对应具体路径和负载模型
- 理解为什么只报平均值不够
- 学会把延迟分位数和 CPU 占用一起看

---

## 3. 推荐推进顺序

1. 定义测试模式：ioctl、mmap、DMA 三条路径至少选两条。
2. 设计样本量、预热轮次和统计字段。
3. 输出 CSV/Markdown 报表。
4. 注明测试环境和限制条件。

---

## 4. 当日验收

- 能生成 bench 数据
- 至少包含 p50/p99 与 CPU 使用率
- 报表可复读、可比较
