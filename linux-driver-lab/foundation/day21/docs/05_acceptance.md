# Day21 验收定义

## 1. Day21 当前阶段的验收

既然当前是“需求分析 + 报告设计”阶段，那么这一步的验收标准不应该是“有没有最终正文”，而应该是：

### 1）独立目录已经建立
Day21 有自己的：
- `README.md`
- `START_HERE.md`
- `docs/`
- `templates/`
- `output/`

### 2）目标与边界清楚
能从 Day21 文档里读出：
- D21 原始需求是什么
- 为什么它不是新实验
- 它从哪里取数
- 哪些边界必须说明

### 3）报告结构已经设计好
已经明确：
- 背景
- 方法
- 数据
- 结论
- 回滚方案

### 4）模板已经可直接用
已经有可以直接填内容的 Day21 报告模板。

如果这四条成立，说明 Day21 的规划阶段已经成立。

## 2. Day21 后续正式交付阶段的验收

当后面继续推进正式正文时，再增加下面这些验收项：

### 1）已有正式输出文件
例如：
- `output/day21_report_final.md`
- `output/day21_report_onepager.md`

### 2）1-2 页内能自洽
只看最终报告，就能回答：
- W3 做了什么
- 结果如何
- 当前推荐配置是什么
- 如何回滚

### 3）结论表达诚实
不会把带条件的结论写成绝对结论。

### 4）能作为讲解稿使用
可以直接拿来给别人讲，也能作为面试/复盘的压缩版材料。
