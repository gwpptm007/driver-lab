## 背景

2026-05-10 初测时使用物理网卡 `ens192/vmxnet3`，两种模式的 `rx_packets=0, tx_packets=0`。根本原因已于 Phase 1 定位：**同主机发包到本地 IP 走 local delivery 短路，XDP hook 不触发**。

本次复测改用 veth pair 拓扑，首次在 Phase 4 验证了完整的 drop 和 reflect 数据路径，且 **首次获得 tx_packets > 0 和 comp_packets > 0**。

## 测试拓扑

```
ping -I veth-peer → veth-peer (10.99.0.2)
                        │
                        v (veth pipe, XDP hook 必定触发)
                        │
                   veth-xdp ← XDP program (bpf_redirect_map → XSKMAP)
                        │
                        v
                   AF_XDP socket → UMEM RX ring
                        │
                        ├── drop mode:  recycle to FILL ring
                        │
                        └── reflect mode: TX ring → sendto() → COMPLETION ring → FILL ring
```

## 关键学习点

### 1. frame 所有权流转（drop 模式）

```
FILL ring (userspace→kernel, 放入空闲 frame)
    ↓
RX ring (kernel→userspace, 填入收到的包)
    ↓
userspace 读取，决定丢弃
    ↓
FILL ring (归还 frame，循环使用)
```

### 2. frame 所有权流转（reflect 模式）

```
FILL ring (userspace→kernel, 放入空闲 frame)
    ↓
RX ring (kernel→userspace, 填入收到的包)
    ↓
userspace 读取，决定反射
    ↓
TX ring (userspace→kernel, 将 frame 提交发送)
    ↓
kernel 完成发送，将 frame 放入 COMPLETION ring
    ↓
userspace 从 COMPLETION ring 消费，归还 FILL ring
    ↓
FILL ring (循环)
```

### 3. TX ring 在 veth 上的行为

veth 的 TX 路径：AF_XDP TX ring → `sendto()` → veth-xdp TX → veth-peer RX。但 veth-peer 上只有 XDP（没有 AF_XDP socket），所以反射的包会被 veth-peer 的协议栈处理（或丢弃，因为 10.99.0.1 不存在）。注意：这**不会形成无限循环**，因为反射的包从 veth-xdp TX 出去，到达 veth-peer，不会回到 veth-xdp 的 RX。

### 4. 为什么 comp_packets == tx_packets

在 reflect 模式中，每个从 TX ring 发送的 frame 最终都会在 COMPLETION ring 中返回。comp_packets=3 == tx_packets=3，说明 TX→COMPLETION 路径完整无误。
