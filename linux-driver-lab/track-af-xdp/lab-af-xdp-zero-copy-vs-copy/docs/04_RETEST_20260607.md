# 04_RETEST_20260607 — 2026-06-07 复测记录

## 背景

2026-05-10 初测时使用物理网卡 `ens192/vmxnet3`，所有模式的 `rx_packets=0`。根本原因已于 Phase 1 定位：**同主机发包到本地 IP 走 local delivery 短路，XDP hook 不触发**。

本次复测改用 veth pair 拓扑，首次在 Phase 3 验证了三个模式的完整探针行为。

## 测试拓扑

```
ping -I veth-peer → veth-peer (10.99.0.2)
                        │
                        v (veth pipe, XDP hook 必定触发)
                        │
                   veth-xdp ← XDP program (bpf_redirect_map → XSKMAP)
                        │
                        v
                   AF_XDP socket → UMEM RX ring → 用户态 poll 收包
```

## 测试命令

```bash
# 确保 veth pair 存在
sudo ip link add veth-xdp type veth peer name veth-peer
sudo ip link set veth-xdp up && sudo ip link set veth-peer up
sudo ip addr add 10.99.0.2/24 dev veth-peer

# 构建
bash scripts/01_build_app.sh

# 03 — skb+copy 基线
echo 'wq123456!' | sudo -S bash -c 'AF_XDP_IFACE=veth-xdp bash scripts/03_run_copy_mode_baseline.sh' &
```

## 结果

### COPY BASELINE (skb + copy) — PASS

```
PROBE_RC=0
AF_XDP_FINAL_STATS rx_packets=3 rx_bytes=126 fill_recycled=3
bye
```

- UMEM / XSK socket / FILL ring / XDP attach / XSKMAP register 全部就绪
- 捕获到 3 个 ARP 包 (42 bytes each)，来自 ping 10.99.0.1 的 ARP 请求
- **PASS_COPY_BASELINE=YES, PASS_RX_TRAFFIC=YES**

### NATIVE COPY (native + copy) — PASS

```
PROBE_RC=0
XDP_ATTACHED ifname=veth-xdp mode=native
AF_XDP_FINAL_STATS rx_packets=3 rx_bytes=126 fill_recycled=3
```

- veth 在 kernel 6.8 上支持 native XDP (XDP_FLAGS_DRV_MODE)
- native mode 下同样能通过 AF_XDP socket 收到流量
- **PASS_NATIVE_COPY=YES**

### ZERO COPY (native + zero-copy) — UNSUPPORTED (expected)

```
xsk_socket__create: Operation not supported
PROBE_RC=1
```

- veth 不支持 zero-copy（无 DMA，无法将 UMEM 映射给硬件）
- 这是**预期失败**，不是程序 bug
- **ZERO_COPY_PROBED=YES, PASS_ZERO_COPY=NO**

### COMPARE_MODES 判定

```text
COPY_BASELINE_STATUS=PASS
NATIVE_COPY_STATUS=PASS
ZERO_COPY_STATUS=UNSUPPORTED_OR_ATTACH_FAIL
PASS_COPY_BASELINE=YES
ZERO_COPY_PROBED=YES
PASS_ZERO_COPY=NO
FALLBACK=USE_SKB_COPY_OR_NATIVE_COPY_IF_AVAILABLE
```

### ethtool XDP 统计

```text
rx_queue_0_xdp_packets: 6
rx_queue_0_xdp_bytes: 168
rx_queue_0_xdp_redirect: 6
rx_queue_0_xdp_drops: 0
```

共 6 个包被 XDP redirect 到 AF_XDP socket（3 个来自 skb+copy，3 个来自 native+copy）。

## 关键学习点

### 1. veth 的 native XDP 支持

kernel 5.12+ 的 veth 驱动实现了 native XDP。在本次测试中，veth 上的 `native+copy` 模式完全正常工作，说明 veth 是一个有效的 native XDP 测试环境。

### 2. zero-copy 需要真正的 DMA

zero-copy 需要网卡驱动将 UMEM 物理页映射给 NIC DMA 引擎。veth 是纯软件的虚拟设备，没有 DMA，因此 `xsk_socket__create` 返回 `Operation not supported`。vmxnet3 同样不支持 zero-copy。

### 3. 模式组合的兼容性层级

```
skb + copy          ← 兼容性最强，始终可用
native + copy       ← 需要驱动支持 native XDP (veth 5.12+, 部分物理网卡)
native + zero-copy  ← 需要驱动实现 AF_XDP ZC (仅部分高性能网卡)
skb + zero-copy     ← 无实际意义
```

### 4. 为什么 ping ARP 包只有 3 个

ping 10.99.0.1（不存在的 IP）触发 ARP 请求。内核 ARP 有退避机制：先发几个 ARP，如果无响应就进入 INCOMPLETE 状态并暂停。因此 100 个 ping 只产生约 3 个 ARP 包被 AF_XDP 捕获。后续帧被 ARP 队列缓存或直接丢弃。
