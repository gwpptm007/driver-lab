# Day21 的数据来源与边界说明

## 1. Day21 的数据来自哪里

Day21 自己不重新发明实验数据，主要复用前面已经形成的结果。

### 推荐主来源
- `docs/W3_REVIEW.md`
- `day15/RESULTS.md`
- `day16/RESULTS_ROUND1.md`
- `day16/RESULTS_ROUND2B.md`
- `day16/RESULTS_SUMMARY.md`

## 2. 哪些信息适合直接取用

### 适合直接取用的
- W3 背景与阶段定义
- baseline / trim1 / trim2 的阶段映射
- Day19 已整理好的对比表口径
- Day20 的交付状态与 suite 结论
- Day20 的回归限制说明

### 不建议重新手算的
- 已经在 Day19 表里整理好的 delta
- 已经在 Day20 里总结好的 delivery/runtime 状态

## 3. 哪些地方必须带边界说明

### 1）跨阶段取数并不一定完全同口径
比如：
- rootfs 内容可能有变化
- perf 工具注入周期可能不同
- 某些对比来自 records，某些来自结果文档

这些都意味着：

> Day21 的数据可以写，但必须诚实写清楚边界。

### 2）D20 当前并不等于“真实 PASS 已完成”
当前 Day20 更明确的结论是：
- 套件结构成熟
- 交付入口齐全
- 当前包缺 image/rootfs/dtb 这类大文件输入件

所以 Day21 里不能把它写成“已经完整跑通最终真实回归”。

## 4. Day21 的引用原则

建议遵守下面三条：

### 原则一：优先用已经归档的稳定结果
先用 Day19 / Day20 已经整理过的输出，而不是到处重新抓零散数据。

### 原则二：遇到口径不完全一致时，先写边界，再写结论
不能反过来先下结论，再把边界藏起来。

### 原则三：短报告里只放主结论，细节回指前序 day
这样 Day21 才能保持 1-2 页，而不会重新膨胀成长文。
