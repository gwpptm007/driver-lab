# 01. stage01 的目标与边界

## 一、目标

`stage01` 只解决一个问题：

> 最小 `net_device` 骨架如何真正落成一个可运行、可观测、可讲解的教学实现。

这里的“最小”，不是说偷工减料，而是主动控制复杂度：

- 先不做真实 RX
- 先不做 NAPI
- 先不做 ring / DMA
- 先不做 virtio-net
- 先把 `ndo_open / stop / start_xmit` 讲透

## 二、为什么这一阶段故意不做复杂数据路径

因为这一阶段最容易出现一个误区：

- 看到接口了，误以为已经“会网络驱动了”
- 写了个 xmit，误以为已经“有收发闭环了”

实际上 `stage01` 的作用是建立一个**北向稳定坐标系**：

- 内核里接口如何被注册出来
- 用户态如何把包送到该接口
- 驱动入口在哪里触发
- 最小统计如何建立

后续所有阶段都会复用这套 northbound 视角。

## 三、本阶段明确不做什么

- 不做 `skb` 深入字段教学（留到 `stage02`）
- 不做 NAPI（留到 `stage03`）
- 不做 ring / DMA / refill（留到 `stage04`）
- 不做 virtio-net（留到 `stage05`）
- 不做 ARM64 迁移（留到 `stage06`）
