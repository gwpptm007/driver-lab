## 测试步骤与结果

### 1. 构建
```bash
# 用户态工具（成功）
cd tools && gcc -o send_stage02_frame send_stage02_frame.c
                   -o recv_stage02_frame recv_stage02_frame.c
# → send_stage02_frame / recv_stage02_frame 编译成功

# 内核模块（成功，需 gcc-12）
make -C /lib/modules/6.8.0-106-generic/build M=$(pwd) modules CC=gcc-12
# → driver/netdev_stage02.ko 编译成功
```

### 2. 模块加载（loop_mode=copy）
```bash
sudo insmod driver/netdev_stage02.ko
```
**dmesg 输出：**
```

nds2: stage02 open: queue started, carrier on, loop_mode=copy
```
**结论: ✅ 模块加载成功，nds2 接口注册**

### 3. 接口 UP
```bash
sudo ip link set dev nds2 up
```
**ip link show nds2：**
```
7: nds2: <BROADCAST,MULTICAST,NOARP,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UNKNOWN
    link/ether d2:3e:b0:56:ee:be brd ff:ff:ff:ff:ff:ff
```

### 4. 环回测试（copy 模式）
```bash
# 终端1：接收
./recv_stage02_frame nds2 0x88B5

# 终端2：发送
./send_stage02_frame nds2 hello_stage02_test 0x88B5
```
**recv 输出：**
```
received 32 bytes on nds2 (ifindex=7, pkttype=PACKET_BROADCAST, proto=0x88b5)
payload=hello_stage02_test
```
**结论: ✅ copy 模式环回成功**

### 5. 切换 clone 模式
```bash
sudo rmmod netdev_stage02
sudo insmod driver/netdev_stage02.ko loop_mode=clone
```
**dmesg 输出：**
```
netdev_stage02: loaded, ifname=nds2 mac=ee:fc:47:63:09:83 loop_mode=clone
nds2: stage02 open: queue started, carrier on, loop_mode=clone
```

### 6. 环回测试（clone 模式）

```
**recv 输出：**

payload=clone_test_payload
```
**stats 显示：**

**结论: ✅ clone 模式环回成功**

## 调用链验证

```
用户态: sendto(AF_PACKET, ETHERTYPE=0x88B5)
    ↓
内核协议栈: __dev_queue_xmit()
    ↓
ndo_start_xmit: stage02_start_xmit()
    ↓
stage02_note_tx() ← TX 统计
    ↓
stage02_build_rx_skb()
    ├── skb_copy() 或 skb_clone() ← loop_mode 控制
    ├── skb_orphan() ← 断开 socket 关联
    ├── rx_skb->dev = ndev
    ├── rx_skb->pkt_type = PACKET_HOST
    └── eth_type_trans() ← 解析以太头
    ↓
netif_rx(rx_skb) ← 注入 RX 路径 ★
    ↓
stage02_note_rx_inject() ← RX 统计
    ↓
dev_consume_skb_any(skb) ← 消费原始 TX skb
    ↓
协议栈 RX 路径
    ↓
用户态: recvfrom(AF_PACKET) ← 收到环回帧
```

## 修复记录

测试过程中发现并修复的问题：

### 问题1: module_param_string 宏名写错
- **现象**: `module_param_string_string` 编译报错
- **原因**: 添加注释时误将 `module_param_string` 写成 `module_param_string_string`
- **修复**: 改为正确的 `module_param_string`

### 问题2: stage02_stats_show 局部变量丢失
- **现象**: `open_count` / `tx_packets` 等变量 undeclared
- **原因**: 添加注释时替换了原有变量声明
- **修复**: 补充完整的局部变量声明列表

### 问题3: 用户态工具 glibc 版本不匹配
- **现象**: `GLIBC_2.38' not found`
- **原因**: 工具在本地新版系统编译，远程是 Ubuntu 22.04
- **修复**: 在远程机器上重新 gcc 编译
