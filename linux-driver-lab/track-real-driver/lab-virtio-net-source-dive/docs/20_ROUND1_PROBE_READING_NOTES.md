# 20_ROUND1_PROBE_READING_NOTES

> 这份文档是对 `03_PROBE_TX_RX_READING_ORDER.md` 的正文补强版，强调“第一轮看 probe 时到底该看什么”。

## 一、看 probe 的正确姿势

第一轮看 `probe()` 时，不要一上来试图解释每一行。  
更合理的顺序是：

1. 先看它前后负责的生命周期位置
2. 再看它内部的大阶段
3. 最后才追某几个你真正关心的 helper

## 二、第一轮只拆四段

### 1. feature / capability 阶段
先看“驱动和设备的契约”是如何建立的。

### 2. netdev 初始化阶段
看设备如何变成 `net_device`，以及私有结构如何挂接。

### 3. queue / napi 建立阶段
看 RX/TX 后续运行所依赖的基础资源和处理骨架如何建立。

### 4. register / bring-up 阶段
看什么时候真正进入网络栈可见状态。

## 三、第一轮不要陷入的误区

### 误区 1：试图一次追完所有 helper
结果通常是既记不住，也不知道主链路在哪。

### 误区 2：只看 `net_device_ops`
会误以为驱动核心复杂度都在对外回调里。

### 误区 3：先看 TX/RX，后看 queue 初始化
这样很容易读到一半失去上下文。

## 四、推荐输出

第一轮看完 probe 后，至少要有：

- 一张 probe 阶段划分图
- 一张结构体关联图
- 一份“初始化 vs 清理”的镜像列表
