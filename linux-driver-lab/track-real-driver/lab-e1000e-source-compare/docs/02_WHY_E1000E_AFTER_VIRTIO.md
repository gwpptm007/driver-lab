# 02_WHY_E1000E_AFTER_VIRTIO

## 为什么先做它

### 1. 它能补“传统 NIC 驱动”视角
`virtio_net` 更强调：
- 半虚拟化设备模型
- feature negotiation
- queue/event 推进模型

而 `e1000/e1000e` 更强调：
- 传统 PCI NIC 驱动组织
- 更直接的硬件寄存器/中断语义
- 更接近“真实物理网卡驱动”的阅读方式

### 2. 它和当前环境连续
你现在已有环境中本来就出现过：
- `e1000`
- `e1000e`
- `vmxnet3`

因此这个专题不是凭空开新方向，而是顺着现有环境的真实设备模型往前走。

### 3. 它最适合拿来和 `virtio_net` 做对照
最值得比较的几个维度：
- 设备模型
- 驱动骨架
- TX / RX 路径
- IRQ / NAPI 组织
- ethtool / stats 暴露
- 控制面与数据面边界
