# 下一步执行计划（专家评审口径）

## 1. 当前最合理的目标

不是继续增加目录数量，而是让当前仓库：

1. 更稳
2. 更统一
3. 更能讲
4. 更适合继续长大

---

## 2. 三阶段动作建议

### 第一阶段：收口与统一（优先级最高）

目标：把当前仓库从“已经很强”推进到“入口清晰、评审顺手”。

建议动作：

1. 统一顶层阅读入口
2. 统一总评文件与路线图
3. 修正所有缺失引用
4. stage06 去个人路径 fallback
5. 统一 stage04 / stage06 的 build/run/smoke 入口

预期收益：

- 项目可读性明显提升
- 评审成本明显下降
- 迁移能力表达更可信

### 第二阶段：强化 netdev 代表作

目标：让第二阶段不只停留在“已经迁移成功”，而是形成新的功能高峰。

建议动作：

1. 继续深挖 stage04 数据路径
2. 对照 `virtio-net` 更细地拆 queue/notify/complete 机制
3. 考虑更真实的 transport/后端抽象
4. 形成“教学型实现 vs 真实内核实现”的对照文档

预期收益：

- 第二阶段作品感更强
- 代码层次进一步拉开
- 更适合对外讲“我如何理解真实网卡驱动”

### 第三阶段：仓库产品化

目标：让项目既能本地交付，也能公开展示。

建议动作：

1. 拆源码包与证据包
2. 控制大体积输出物进入源码包
3. 保留代表性 records 与报告样例
4. 形成对外版 README / gallery / highlights

预期收益：

- 仓库更适合 GitHub 展示
- 更适合长期维护
- 更适合作为个人作品集
