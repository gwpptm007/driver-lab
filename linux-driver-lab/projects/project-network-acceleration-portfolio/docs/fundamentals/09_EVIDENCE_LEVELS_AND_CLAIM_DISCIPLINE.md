# 09. 证据等级与对外表述

作品集的可信度来自结论与证据严格匹配，而不是把每条实验说到最大。每次展示、简历或面试表达前，先为结论标注等级。

## 9.1 建议的五级证据

| 等级 | 名称 | 需要的证据 | 合理表述 |
| --- | --- | --- | --- |
| E0 | 设计/阅读 | 文档、代码阅读或方案 | 已理解/已设计，尚未验证 |
| E1 | 单元语义 | 可重复 unit test 或受控 mock | 已验证字段、状态机或局部语义 |
| E2 | 软件路径 | pcap、veth、RXE、虚拟环境端到端计数 | 已验证当前软件环境下的功能闭环 |
| E3 | 单机硬件 | 真实 NIC/RNIC、完整环境快照、对照数据 | 已验证该硬件与配置下的行为/性能 |
| E4 | 多机/长稳生产样本 | 多机、故障、长稳、资源/运维证据 | 已获得特定场景的部署级证据 |

任何等级都不自动泛化到另一型号、另一驱动、另一拓扑或更高并发。

## 9.2 当前材料的正确归类

| 方向 | 当前可用结论 | 典型等级 | 不能延伸为 |
| --- | --- | --- | --- |
| DPDK pcap | parser/forward/rewrite 的软件路径可验证 | E2 | 真实 NIC 线速 |
| AF_XDP veth | XDP、socket、UMEM/ring 语义可验证 | E2 | 驱动 zero-copy |
| RXE RDMA | verbs、MR/QP/CQ、RC 流程可验证 | E2 | RNIC/RoCE 性能 |
| DPDK-RDMA Gateway | bounded staging、generation、CQE drain 的端到端闭环 | E2 | 生产级多 QP/重试/硬件吞吐 |
| SmartNIC/DPU map | 实施步骤与验收设计已明确 | E0 | 已完成 representor/offload |

## 9.3 每个结论的证据包

一个可复验结论至少包含：

1. **问题和假设**：要证明什么，不要证明什么；
2. **环境**：硬件/软件版本、拓扑、NUMA、权限和 provider；
3. **输入**：流量、包/WR 大小、并发、持续时间、warm-up；
4. **操作**：命令、配置、版本、控制面状态；
5. **观测**：计数守恒、错误、trace/日志、设备状态；
6. **对照**：与哪条 baseline 或哪种配置比较；
7. **结论与边界**：适用条件、失败条件、未覆盖项。

缺失任意一项时，结论应降级，而不是通过更强的措辞填补。

## 9.4 对外表达模板

推荐：

> 在固定的 pcap + RXE 实验环境中，我验证了 DPDK ingress 到 RC WRITE/CQE 回收的端到端生命周期；结果用于证明契约和错误处理，不作为真实 RNIC 性能结论。

不推荐：

> 我实现了高性能零拷贝 RDMA 网关，性能可用于生产。

前者准确说明工作、证据和边界，反而更容易引出深入讨论。

## 9.5 升级证据的条件

E2 升到 E3，通常需要真实硬件、完整拓扑快照、可比较 baseline、多次运行、端口/队列/CQE 统计和失败样本。E3 升到 E4，还需要长时间运行、故障演练、升级/回滚、多租户资源压力和运维证据。
